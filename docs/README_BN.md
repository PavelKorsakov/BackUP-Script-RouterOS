# MikroTik Backup Script

**MikroTik RouterOS ডিভাইসের ব্যাকআপ নিন।**

এই স্ক্রিপ্ট RouterOS চালিত ডিভাইসের ব্যাকআপ তৈরি করে—ম্যানুয়ালি অথবা শিডিউলারের মাধ্যমে স্বয়ংক্রিয়ভাবে *(শিডিউলারটি আপনাকে আলাদাভাবে কনফিগার করতে হবে)*।
`mikrotik-backup.sh` একটি স্বয়ংসম্পূর্ণ স্ক্রিপ্ট, তবে কিছু ফিচার `option.cfg` দিয়ে কনফিগার করা যায়।

<br>

## স্ক্রিপ্টের বৈশিষ্ট্য

| বৈশিষ্ট্য | যেভাবে কাজ করে |
|---|---|
| একক-ডিভাইস মোড | CLI অপশন ব্যবহার করে একটি ডিভাইসের ব্যাকআপ তৈরি করে |
| ব্যাচ প্রসেসিং | DeviceList-এ থাকা ডিভাইসগুলো ধারাবাহিকভাবে প্রসেস করে; Oxidized থেকে তালিকা ইমপোর্ট করতে পারে |
| ব্যাকআপ ফরম্যাট | `.rsc`, `.backup`, অথবা পরপর উভয় ফরম্যাট তৈরি করে |
| ব্যাকআপ মোড | compact, terse ও verbose এক্সপোর্ট এবং বাইনারি ব্যাকআপ এনক্রিপশন সমর্থন করে |
| ইনক্রিমেন্টাল ব্যাকআপ | পরিবর্তন শনাক্ত হলেই শুধু ব্যাকআপ রেখে দিতে পারে |
| মাসিক আর্কাইভ | ক্যালেন্ডার সীমায় পুরোনো ব্যাকআপ ও লগ আর্কাইভ করতে পারে |
| লগিং | সাধারণ ধাপগুলো `main.log`-এ এবং ডিভাইসের অপারেশনগুলো `devicename.log`-এ রেকর্ড করে |
| কনফিগারেশন মেনু | সুবিধাজনক সেটআপ ও পরিচালনার জন্য ইন্টারঅ্যাক্টিভ মেনু দেয় |
| লোকালাইজেশন | রুশ ও ইংরেজি অন্তর্ভুক্ত করে এবং বাহ্যিক লোকালাইজেশন ফাইল সমর্থন করে |
| ব্যাকআপ স্টোরেজ | NAS-সহ যেকোনো ব্যাকআপ ডিরেক্টরি ব্যবহার করতে পারে |
| NAS পরিচালনা | ব্যাকআপ তৈরির আগে স্টোরেজ উপলভ্য কি না পরীক্ষা করে |

## সিস্টেমের প্রয়োজনীয়তা ও শুরু করার নিয়ম

**আবশ্যক:**
GNU Bash 4.4 বা পরবর্তী সংস্করণ এবং ইনস্টল করা **SSH**, **SCP** ও **SSHPass** ইউটিলিটি।
শুধু মাসিক ব্যাকআপ আর্কাইভ করার জন্য **zip** প্রয়োজন। সব আবশ্যক ইউটিলিটি ও সেগুলোর ইনস্টলেশন কমান্ড [নির্ভরতা](bn/INSTALL.md#নির্ভরতা) অংশে দেওয়া আছে।
*(বি.দ্র.: কোনো আবশ্যক ইউটিলিটি না থাকলে স্ক্রিপ্ট ত্রুটিসহ বন্ধ হয়। এটি প্রত্যাশিত আচরণ।)*

**ঐচ্ছিক:**
বাহ্যিক স্টোরেজ মাউন্ট করার জন্য **autofs**, **davfs2**, **rclone** এবং অন্যান্য টুল।

**ইনস্টলেশন:**
ডাউনলোড ও সেটআপের নির্দেশনার জন্য [ইনস্টলেশন](bn/INSTALL.md) দেখুন।

ডাউনলোড করা ফাইলগুলো যে ডিরেক্টরিতে আছে, সেখানে নিচের কমান্ডগুলো চালান:

নিচের command blockটি GitHub Release থেকে নেওয়া file-এর জন্য। Git source checkout-এ Release-এর জন্য তৈরি `SHA256SUMS` থাকে না; source checkout ব্যবহার করলে `chmod 700 mikrotik-backup.sh` থেকে শুরু করে version ও help check চালান।

```bash
sha256sum -c SHA256SUMS &&
chmod 700 mikrotik-backup.sh &&
./mikrotik-backup.sh --language en --version &&
./mikrotik-backup.sh --language ru --help
```

চেকসম যাচাই **ব্যর্থ হলে**, **ফাইলটি চালাবেন না!!!**

## স্ক্রিপ্ট চালানোর পদ্ধতি

**অতিরিক্ত অপশন ছাড়াই ফাইল চালান** *(`option.cfg` অনুপস্থিত বা অবৈধ হলে)*
স্ক্রিপ্টের পাশে `option.cfg` না থাকলে অথবা ফাইলটিতে ব্যবহারযোগ্য কোনো সেটিং না থাকলে, `option.cfg` তৈরি বা সম্পাদনার জন্য Configuration Editor খুলবে।

**অতিরিক্ত অপশন ছাড়াই ফাইল চালান** *(বৈধ `option.cfg` ও `devicelist.cfg` থাকলে)*
ব্যবহারযোগ্য সেটিং আগে থেকেই থাকলে স্ক্রিপ্ট ব্যাচ প্রসেসিং শুরু করবে।

**একটি অপশন দিয়ে স্ক্রিপ্ট চালান:**

| কাজ | কমান্ড |
|---|---|
| ইন্টারঅ্যাক্টিভ মেনু খুলুন | `./mikrotik-backup.sh -i` |
| BackUP Master খুলুন | `./mikrotik-backup.sh -b` |
| `option.cfg` তৈরি বা সম্পাদনা করুন | `./mikrotik-backup.sh -e` |
| সম্পূর্ণ CLI সহায়তা দেখুন | `./mikrotik-backup.sh -h` |
| একটি ডিভাইসের ব্যাকআপ চালান | সম্পূর্ণ CLI ত্রয়ী দিন: ডিভাইসের ঠিকানা, ব্যবহারকারী ও পাসওয়ার্ড |

এখানে সবচেয়ে গুরুত্বপূর্ণ অপশন হলো `-i`, যা ইন্টারঅ্যাক্টিভ মেনু খোলে। সেখান থেকে আপনি:

- BackUP Master ব্যবহার করে ডিভাইসের প্যারামিটার দিতে, ব্যাকআপ তৈরি করতে এবং নির্বাচিত প্যারামিটার দিয়ে `devicelist.cfg` তৈরি বা বাড়াতে পারেন;
- Configuration Editor ব্যবহার করে `option.cfg` তৈরি বা সম্পাদনা করতে পারেন;
- CLI সহায়তা দেখতে পারেন;
- স্ক্রিপ্টের ফিচার সম্পর্কে সংক্ষিপ্ত নির্দেশিকা পড়তে পারেন।

সঠিক `-a=...`, `-u=...` ও `-p=...` ফর্মসহ সম্পূর্ণ CLI রেফারেন্সের জন্য [কমান্ড-লাইন রেফারেন্স](bn/CLI.md) দেখুন।

## ফলাফল কোথায়, অর্থাৎ “আমার ব্যাকআপগুলো কোথায়???”

ডিফল্টভাবে ডিভাইসের ব্যাকআপ স্ক্রিপ্টের পাশের `backups` ডিরেক্টরিতে রাখা হয়। ডিরেক্টরিটি না থাকলে স্ক্রিপ্ট তা তৈরি করে।
*(বি.দ্র.: আপেক্ষিক `backups` পাথটি বর্তমান working directory থেকে নয়, স্ক্রিপ্টের ডিরেক্টরি থেকে resolve করা হয়!)*

একক-ডিভাইস রানে আলাদা ডিভাইস সাবডিরেক্টরি তৈরি হয় না:

```text
backups/
├── main.log
├── Router-A_YYYY-MM-DD_HH-MM.rsc
├── Router-A_YYYY-MM-DD_HH-MM.backup
└── Router-A_YYYY-MM-DD_HH-MM.log
```

ব্যাচ মোডে প্রতিটি ডিভাইসের নিজস্ব ডিরেক্টরি থাকে:

```text
backups/
├── main.log
└── Router-A/
    ├── Router-A_YYYY-MM-DD_HH-MM.rsc
    ├── Router-A_YYYY-MM-DD_HH-MM.backup
    ├── Router-A.log
    └── archive/
        └── DD.MM.YYYY.zip
```

এই বিন্যাসগুলো উদাহরণ মাত্র; প্রতিটি রানের পরে সব ফাইল থাকবে—এমন নিশ্চয়তা নেই।
প্রযোজ্য প্রথম entry লেখা হলেই একটি লগ তৈরি হয়।
`option.cfg`-এর `MainLogPath` অপশন `main.log`-কে `/var/log/` বা অন্য উপযুক্ত ডিরেক্টরিতে সরাতে পারে।
ব্যাকআপ, আর্কাইভ ও লগ ডিরেক্টরি কনফিগার করার বিস্তারিত জানতে [কনফিগারেশন](bn/OPTIONS.md) দেখুন।

<br>

## মাসিক আর্কাইভ

এই ফিচার ডিফল্টভাবে নিষ্ক্রিয়। স্ক্রিপ্ট শিডিউল অনুযায়ী চললে `option.cfg`-এ `MonthlyArchive=true|1...28` সেট করে আগের সময়পর্বের সব ব্যাকআপ আর্কাইভ করার সময় নির্বাচন করুন।

সেই দিনে ব্যাচ রানের কাজের ক্রম বদলে যায়: প্রথমে ব্যাকআপ ডিরেক্টরিতে জমা হওয়া সব যোগ্য ফাইল ও ডেটা আর্কাইভ করে, তারপর বর্তমান তারিখের ব্যাকআপ তৈরি করে।

আর্কাইভের নাম আগের ক্যালেন্ডার দিনের নামে হয়। যেমন, 1 অক্টোবরের রান `30.09.YYYY.zip` তৈরি করে।

*(বি.দ্র.: স্ক্রিপ্ট প্রতিদিন না চললে প্রয়োজনীয় তারিখের জন্য আলাদা scheduled job তৈরি করতে হবে। স্ক্রিপ্ট প্রতিদিন বা তার চেয়ে বেশি বার চললে আলাদা job দরকার নেই।)*

যে কারণেই হোক, বাদ পড়া মাসিক প্রচেষ্টা দৈনিক রান দিয়ে পরে পূরণ করা হয় না।
পরবর্তী নির্ধারিত মাসিক প্রচেষ্টা জমে থাকা সব পুরোনো ডেটা একটি আর্কাইভে নেয়, backlog কয়েক মাসের হলেও। `main.log` আর্কাইভ করা হয় না।

সম্পূর্ণ নিয়ম, উদাহরণ ও failure behavior-এর জন্য [মাসিক আর্কাইভ](bn/BACKUPS.md#monthly-archive) দেখুন।

## পরিধি ও সীমাবদ্ধতা

স্ক্রিপ্ট ব্যাকআপ তৈরি করে, কিন্তু RouterOS-এর কনফিগারেশন পুনরুদ্ধার করে না।
বর্তমান সংস্করণ ইমেল বা মেসেঞ্জার বিজ্ঞপ্তি পাঠায় না এবং পুরোনো ZIP ফাইল বয়স অনুযায়ী মুছে দেয় না।
পুনরুদ্ধার পদ্ধতি, বাহ্যিক সংরক্ষণনীতি এবং ফলাফল পর্যবেক্ষণের দায়িত্ব প্রশাসকের।

SSH profile password authentication ব্যবহার করে এবং host-key verification নিষ্ক্রিয় রাখে।
একটি `.backup` ফাইল এনক্রিপ্ট করলে `.rsc` ফাইল, কনফিগারেশন ফাইল বা ZIP আর্কাইভ এনক্রিপ্ট হয় না।
বাস্তব ব্যবহারের আগে [নিরাপত্তা মডেল](bn/SECURITY.md) পড়ুন।
