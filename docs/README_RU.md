# MikroTik Backup Script

**Резервное копирование MikroTik RouterOS.**

Данный скрипт предназначен для снятия резервных копий с устройств под управлением RouterOS  
как в ручном, так и в автоматическом режиме с помощью планировщика *(настраивается самостоятельно)*.  
Файл `mikrotik-backup.sh` является самодостаточным скриптом, но некоторые его возможности могут быть изменены с помощью файла `option.cfg`.

<br>

## Функционал скрипта

| Возможности | Как работает |
|---|---|
| Одиночный режим | Снятие копии с одного устройства с помощью ключей CLI |
| Пакетная обработка | Последовательный обход устройств, перечисленных в DeviceList; импорт списка из Oxidized |
| Формат копий | Опционально: `.rsc`, `.backup` или оба формата последовательно |
| Режим копий | Опционально: compact, terse, verbose; шифрование бинарных копий |
| Инкрементность | Опционально: возможность сохранять резервные копии только при наличии изменений |
| Ежемесячный архив | Опционально: архивирование старых копий и журналов по календарной границе |
| Журналирование | Общие этапы записываются в `main.log`, а работа с устройствами записывается в `devicename.log` |
| Меню настройки | Для удобства настройки и использования вызывается интерактивное меню |
| Локализация | Встроенные русский и английский языки, подключение внешних файлов локализации |
| Хранилище копий | Опционально: задать любой каталог для хранения копий, включая NAS |
| Работа с NAS | Проверка доступности хранилища перед созданием резервной копии |

## Требования к системе и начало работы

**Обязательно:**  
GNU Bash 4.4 или новее, установленные утилиты: **SSH**, **SCP**, **SSHPass**,
**zip** *– только если нужна ежемесячная архивация резервных копий*. Все необходимые утилиты и команды их установки перечислены в разделе [Зависимости](ru/INSTALL.md#зависимости).  
*(N.B. Без обязательных для работы утилит скрипт аварийно завершит работу, и это его нормальное поведение.)*



**Опционально:**  
**autofs**, **davfs2**, **rclone** и прочие утилиты монтирования внешних накопителей.

**Установка:**  
Получение файлов и подготовка к работе описаны в разделе [Установка](ru/INSTALL.md).

В каталоге со скачанными файлами выполните:

Блок команд ниже рассчитан на файлы, полученные из GitHub Release. В Git-клоне исходного дерева генерируемого `SHA256SUMS` нет; для такого варианта начинайте с `chmod 700 mikrotik-backup.sh`, а затем выполняйте проверки версии и справки.

```bash
sha256sum -c SHA256SUMS &&
chmod 700 mikrotik-backup.sh &&
./mikrotik-backup.sh --language en --version &&
./mikrotik-backup.sh --language ru --help
```

Если проверка суммы завершилась ошибкой, **не запускайте файл!!!**

## Способы запуска

**Запуск файла БЕЗ указания дополнительных ключей** *(при отсутствии или некорректности файла `option.cfg`)*  
Если файла `option.cfg` нет рядом со скриптом или в нём нет ни одной пригодной настройки, скрипт вызовет открытие «Редактора конфигурации» для создания или редактирования файла опций `option.cfg`.

**Запуск файла БЕЗ указания дополнительных ключей** *(при наличии исправных файлов `option.cfg` и `devicelist.cfg`)*  
Если пригодные настройки уже есть, скрипт перейдёт к пакетному копированию.


**Запуск скрипта с указанием ключа:**

| Задача | Способ |
|---|---|
| Открыть интерактивное меню | `./mikrotik-backup.sh -i` |
| Открыть Мастер резервного копирования | `./mikrotik-backup.sh -b` |
| Создать или изменить `option.cfg` | `./mikrotik-backup.sh -e` |
| Получить полную справку по ключам CLI | `./mikrotik-backup.sh -h` |
| Выполнить одиночный запуск | Полная CLI-тройка: адрес устройства, пользователь, пароль |

Первый по важности тут ключ `-i`, открывающий интерактивное меню, в котором Вы можете:

- с помощью «Мастера резервного копирования», заполнив параметры устройства, снять его резервные копии, создать или дополнить файл `devicelist.cfg`, занеся в него выбранные параметры устройства;
- с помощью «Редактора конфигурации» создать и/или отредактировать файл опций `option.cfg`;  
- получить справку по ключам CLI;
- прочитать краткую инструкцию по функционалу скрипта.

Полную справку по ключам CLI, включая точные формы `-a=...`, `-u=...`, `-p=...`,  
можно посмотреть в [Справочнике командной строки](ru/CLI.md).

## Где хранятся результаты, или «Где мои бэкапы???»

По умолчанию резервные копии устройств хранятся в каталоге `backups` рядом со скриптом. Если такого каталога ещё нет, скрипт создаст его самостоятельно.  
(*N.B. `backups` отсчитывается именно от каталога скрипта, а не от текущего каталога запуска!*)



Обратите внимание, что в режиме одиночного запуска отдельного подкаталога для устройства нет, то есть:

```text
backups/
├── main.log
├── Router-A_YYYY-MM-DD_HH-MM.rsc
├── Router-A_YYYY-MM-DD_HH-MM.backup
└── Router-A_YYYY-MM-DD_HH-MM.log
```

В пакетном же режиме у каждого устройства будет свой каталог:

```text
backups/
├── main.log
└── Router-A/
    ├── Router-A_YYYY-MM-DD_HH-MM.rsc
    ├── Router-A_YYYY-MM-DD_HH-MM.backup
    ├── Router-A.log
    └── archive/
        └── DD.MM.YYYY.zip
```

Это примеры размещения, а не обязательный набор файлов после каждого запуска.
Журнал создаётся при первой подходящей записи.
С помощью опции `MainLogPath` в файле `option.cfg` можно перенести `main.log`, например, в директорию `/var/log/` либо в любой другой удобный для Вас каталог.  
Подробно ознакомиться с настройкой каталога хранения архивов, логов и т. д. можно в разделе [Конфигурация](ru/OPTIONS.md).

## Ежемесячное архивирование

По умолчанию этот функционал отключён. Если планируется работа скрипта по расписанию, то с помощью опции `MonthlyArchive=true|1...28` в файле `option.cfg`
можно задать нужную Вам точку для архивации всех резервных копий за предыдущий период.  

При работе скрипта в пакетном режиме приоритет работы в этот день сместится: сначала будет запущена процедура архивирования всех допустимых данных, накопившихся в каталоге резервных копий, и только затем будут созданы резервные копии за эту дату.  

Архив получает имя предыдущего календарного дня: например, при запуске 1 октября это будет `30.09.YYYY.zip`.  

*(N.B. Тут необходимо заметить, что если Ваше расписание планируется НЕ ежедневным, то для работы этого функционала будет необходимо создать отдельное задание на нужную Вам дату. Если же запуск скрипта планируется ежедневно или чаще, то отдельного задания не требуется.)*

Пропущенная месячная попытка (неважно, в силу каких причин) не догоняется ежедневными запусками.
Следующая штатная попытка забирает все накопившиеся старые данные в один архив,
даже если они относятся к нескольким месяцам. `main.log` не архивируется.

Полные правила, примеры и последствия ошибок этого режима можно посмотреть в разделе **[Ежемесячные архивы](ru/BACKUPS.md#monthly-archive)**.

## Границы применения

Скрипт снимает копии, но не восстанавливает конфигурацию на маршрутизаторе.  
В текущей версии он не отправляет уведомления по почте или в мессенджеры и не удаляет старые ZIP по возрасту.  
Процедуру восстановления, внешнюю ротацию и контроль результатов организует администратор.  

SSH-профиль использует парольную аутентификацию и отключённую проверку ключа сервера.  
Шифрование `.backup` не шифрует `.rsc`, файлы конфигурации или ZIP.  
Перед эксплуатацией прочитайте [модель безопасности](ru/SECURITY.md).
