# Логирование

[Оглавление](../README_RU.md)

## Общий журнал и журналы устройств

Ход работы скрипта записывается в основной журнал `main.log`, а подробности работы с каждым устройством сохраняются в его отдельном журнале.

В `main.log` можно посмотреть подготовку списка устройств, ход пакетной обработки и результаты опроса устройств. Ошибки, возникшие до определения конкретного устройства, тоже записываются сюда.

В журнале устройства находятся сведения о получении `.rsc` и `.backup`, повторных попытках, сравнении копий и архивировании. То есть если требуется выяснить, что произошло при копировании конкретного устройства, смотрим именно его журнал. Все эти подробности в `main.log` не дублируются.

## Где хранятся журналы

По умолчанию основной журнал размещается в каталоге `backups` рядом со скриптом. Журналы устройств находятся рядом с их резервными копиями:

| Журнал | Расположение |
|---|---|
| Основной журнал | `<BackupRoot>/main.log` |
| Устройства в пакетном режиме | `<BackupRoot>/<DeviceName>/<DeviceName>.log` |
| Устройства в одиночном режиме | `<BackupRoot>/<DeviceName>_YYYY-MM-DD_HH-MM.log` |

В пакетном режиме новые записи дописываются в один и тот же журнал устройства. При одиночном копировании его имя содержит ту же дату и время, что и имена резервных копий этого запуска.

### Отдельный каталог для main.log

Если Вам удобнее хранить основной журнал отдельно от копий, укажите нужный каталог в параметре `MainLogPath` файла `option.cfg`:

```ini
MainLogPath=/var/log/mikrotik-backup
```

В этом случае журнал будет находиться в `/var/log/mikrotik-backup/main.log`. Журналы устройств останутся на своих местах.

При пустом значении `MainLogPath=` используется текущий `BackupRoot`. Относительный путь, например `MainLogPath=logs`, указывает на каталог рядом со скриптом, а не внутри хранилища копий.

*(N.B. В `MainLogPath` указывается каталог, а не полное имя файла. Сам каталог должен уже существовать и быть доступен для записи пользователю, от которого запускается скрипт.)*

## Подробность журналирования

За количество выводимой и записываемой информации отвечает параметр `LogLevel`. По умолчанию используется значение `2`:

| Значение | Ход работы в терминале | Записи в файлах журналов |
|---|---|---|
| `0` | Только ошибки | Только ошибки |
| `1` | Основные этапы и их результаты | Краткий журнал |
| `2` | Основные этапы и их результаты | Подробный журнал |
| `3` | Основные этапы и текущие подоперации | Подробный журнал |

**Ошибки записываются при любом уровне.** Краткий журнал содержит основные этапы и их результаты, подробный дополнительно сохраняет выполняемые внутри них операции.

Изменить уровень можно в файле `option.cfg` или через «Редактор конфигурации»:

```ini
LogLevel=3
```

Для одного запуска уже подготовленного пакетного копирования можно указать его через CLI:

```bash
mikrotik-backup.sh --log-level=3
```

Значение в файле опций от этого не изменится. Таким же образом расположение основного журнала для текущего запуска можно задать ключом `--main-log-path`.

В «Мастере резервного копирования» отдельных полей для `LogLevel` и `MainLogPath` нет. При выполнении используются настройки журналирования текущего запуска.

## Как выглядят записи

Журналы являются обычными текстовыми файлами. В каждой записи указываются дата и время по часам хоста, на котором выполняется скрипт. Цвета и индикаторы ожидания в файл не записываются.

Пример записей в `main.log`:

```text
[2026-10-01 01:00:00] [PID:12345] Пакетная обработка устройств
[2026-10-01 01:00:15] [PID:12345] [OK] Пакетная обработка устройств
```

В основном журнале также указывается PID процесса. По нему можно различить записи нескольких одновременно работающих экземпляров скрипта.

В журнале устройства PID не добавляется. Пример фрагмента подробного журнала:

```text
[2026-10-01 01:00:05] Получение бинарного бэкапа
[2026-10-01 01:00:06] [1] Очистка кэша DNS
[2026-10-01 01:00:07] [2] Очистка истории консоли
[2026-10-01 01:00:12] [OK] Получение бинарного бэкапа
```

`[OK]` означает успешное завершение операции. При ошибке используется `[ER]` и указывается её код, например `[53]`. Нумерация подопераций `[1]`, `[2]` и далее начинается заново внутри каждого основного этапа.

Если после неудачной попытки повтор прошёл успешно, в журнале останутся и прежняя ошибка, и последующий успешный результат.

Язык записей совпадает с языком интерфейса и определяется настройкой `Language`. Подробнее о выборе языка и переводах можно прочитать в [LOCALIZATION.md](LOCALIZATION.md).

## Вывод в терминале

При ручном запуске ход работы виден на экране. Пока операция выполняется, рядом с ней отображается индикатор ожидания. По завершении он сменяется на зелёный `[OK]` или красный `[ER]` с кодом ошибки.

На уровнях `1` и `2` показываются основные этапы. На уровне `3` под выполняемым этапом также видна текущая подоперация, которая сменяется следующей по мере работы. В пакетном режиме дополнительно показывается, какое устройство сейчас обрабатывается.

*(N.B. При запуске без терминала, например из планировщика или с перенаправлением вывода, этот экранный вывод отсутствует. Файловые журналы при этом продолжают работать в соответствии с выбранным уровнем.)*

## Накопление и архивирование журналов

Файл журнала создаётся при первой записи. При `LogLevel=0` и отсутствии ошибок новые журналы не создаются, а существующие остаются без новых записей.

Основной журнал и пакетные журналы устройств дополняются, а не перезаписываются при каждом запуске. Новые проходы отделяются пустой строкой.

`main.log` не архивируется и не удаляется по возрасту. Его ротацию Вы настраиваете самостоятельно.

Если включено ежемесячное архивирование, накопленный пакетный журнал устройства попадает в ZIP целиком, вместе с его резервными копиями. После успешного сохранения архива упакованный журнал удаляется из каталога устройства, а результат архивации и последующая работа записываются уже в новый файл журнала.

При повторном обновлении того же ZIP история внутри него дополняется, а не заменяется новым журналом. Если архив сохранить не удалось, прежний журнал остаётся на месте, и ошибка записывается в него.

Журналы одиночных CLI-запусков архивируются вместе с копиями из общего каталога. Порядок архивирования в обоих режимах описан в [BACKUPS.md](BACKUPS.md#monthly-archive).

## Если записать журнал не удалось

Недостаток прав, недоступный каталог или другая ошибка записи журнала не останавливают само резервное копирование. Скрипт регистрирует предупреждение и продолжает работу, если она возможна.

О недоступности `main.log` сообщается один раз за запуск, а о недоступности журнала устройства один раз за его обработку. Если основной журнал доступен, ошибка записи журнала устройства будет зафиксирована в нём.

При отсутствии других ошибок такой запуск завершится с кодом `1`, то есть с предупреждением. Ошибка самого копирования этим предупреждением не заменяется.

Расшифровка кодов и поиск причин ошибок описаны в [TROUBLESHOOTING.md](TROUBLESHOOTING.md#result-codes).

*(N.B. Подробный уровень `3` не включает запись паролей или полных команд подключения. О защите учётных данных и файлов скрипта можно прочитать в [SECURITY.md](SECURITY.md).)*
