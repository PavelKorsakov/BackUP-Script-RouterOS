# Конфигурация

[Оглавление](../README_RU.md)

## Два слова в начале
Файл `option.cfg` является опциональным способом изменить настройки скрипта, используемые им по умолчанию.  
Для того чтобы настройки, перечисленные в этом файле, были подхвачены скриптом во время его выполнения, 
файл `option.cfg` должен находиться рядом (в одном каталоге) с `mikrotik-backup.sh`.  

Сама структура файла очень простая: это перечень данных вида `Ключ=значение`, т. е. это не shell-скрипт.  
Никакой подстановки переменных и выполнения команд в нём не производится.

## Пригодность конфигурации для запуска

Даже одна корректная распознанная строка делает конфигурацию пригодной.
Полный набор настроек перечислять не нужно: если какая-то из опций по умолчанию Вам подходит, то её наличие в файле `option.cfg` не обязательно.

Но если файл пустой или в нём только комментарии, неизвестные ключи либо непригодные значения, скрипту просто нечего из него взять.
В таком случае настройки останутся «по умолчанию».

**И тут есть нюанс!!!**  
Если при этом запустить скрипт без аргументов, резервное копирование не начнётся. Вместо него скрипт попытается открыть «Редактор конфигурации».
То же самое произойдёт, если файл `option.cfg` вообще отсутствует. 
Сохраните нужные настройки и запустите скрипт повторно.  
*(N.B. Для открытия редактора нужен терминал. Если такой запуск происходит
без терминала, например из планировщика, скрипт завершится ошибкой `31`.
Поэтому перед настройкой автоматического запуска подготовьте
файл `option.cfg`.)*

**Порядок чтения опциональных параметров:**  
У скрипта есть приоритет чтения параметров. Если файл `option.cfg` отсутствует, будут применены настройки «по умолчанию», т. е. вшитые в тело скрипта.
Если файл существует и прочитан, то перечисленные в нём <mark>корректные</mark> параметры заменят соответствующие значения «по умолчанию».  

И самое главное!!! Если тот же параметр указан при запуске через CLI, то главным становится именно значение, переданное через CLI. 
То есть в обычном одиночном и пакетном выполнении приоритет такой:  
**Встроенные значения** → **Пригодные строки option.cfg** → **CLI**

*(N.B. Отсутствие файла и невозможность его прочитать не являются одним и тем же.
Если `option.cfg` существует, но скрипт не может его прочитать, выполнение
завершится ошибкой конфигурации с кодом `21`, а не продолжится
с настройками «по умолчанию».)*


## Как читается файл
Строка делится по первому `=`. Имена ключей регистронезависимы, но дефис и подчёркивание не взаимозаменяемы.
Пустые строки и строки с первым непробельным `#` игнорируются. Неизвестная или непригодная строка не отменяет корректные соседние.
Для повторного ключа действует последнее пригодное значение.

У обычных значений внешние пробелы удаляются.  
**Важно:** у `Login`, `Password` и `encrypt` всё после первого `=` сохраняется буквально.
Не добавляйте кавычки ради shell-синтаксиса: они станут частью значения.
Не пишите комментарий после пароля. Для комментария используйте отдельную строку.

Один BOM в начале файла и окончания строк CRLF поддерживаются.
Читаемая символическая ссылка на обычный файл допустима.
Проблема доступа или неподходящий тип объекта не равнозначны пустому файлу
и приводят к ошибке конфигурации.


## Создание, редактирование и сохранение файла 'option.cfg'
Самый простой способ создать этот файл: запустить скрипт с ключом `-e`.
```bash
./mikrotik-backup.sh -e
```
Откроется «Редактор конфигурации», где будут перечислены главные опции. 
Если все строки не помещаются в окне терминала, список прокручивается автоматически при перемещении стрелками вверх и вниз.  
Пункты «Сохранить» и «Отмена» находятся в конце этого же списка.  
Переходим по меню, указывая нужные Вам параметры → нажимаем «Сохранить» → (Вы восхитительны) файл создан.

Тут, конечно, надо понимать, что в процессе работы с интерактивным меню редактор меняет настройки именно в памяти.
И только после нажатия «Сохранить» будет записан полный -*канонический*- файл.

Когда у Вас ещё нет файла `option.cfg`, то при запуске редактора он будет заполнен как раз «значениями по умолчанию».  
Однако когда файл `option.cfg` уже создан и Вы исправили значения параметров на какие-то свои, то при запуске «Редактора конфигурации» его поля будут заполнены уже Вашими данными, а не «значениями по умолчанию».

Второй вариант создания 'option.cfg': ручной. Т. е. да, открываем ручками Ваш любимый текстовый редактор и начинаем вручную указывать нужные Вам настройки-параметры.  
Где их взять? Смотрим ниже:


## Настройки и значения по умолчанию

| Ключ | По умолчанию | Значение и назначение |
|---|---|---|
| `Language` | `auto` | `auto` или две ASCII-буквы, например `ru`, `en`, `de` |
| `SshPort` | `22` | Порт `1`–`65535`; скрыт в редакторе, виден в Master |
| `UseOxidized` | `false` | Импортировать устройства из Oxidized |
| `IgnoreOxiAccess` | `true` | Разрешить прежний DeviceList при сбое чтения/разбора Oxidized; только файл |
| `OxidizedHome` | Пусто | Каталог с `config` и `router.db` |
| `UseIdentityName` | `true` | Использовать живой RouterOS Identity для имени |
| `backup_type` | `both` | `configuration`, `binary`, `both` |
| `UseIncremental` | `true` | Сравнивать новую проверенную резервную копию с предыдущей; при `false` сохранять каждую новую копию без сравнения |
| `export_format` | `compact` | `compact`, `terse`, `verbose` |
| `show_sensitive` | `true` | Включать чувствительные значения в `.rsc` |
| `encrypt` | Пусто | Пароль шифрования `.backup`; пусто означает отсутствие шифрования |
| `encrypt_type` | `aes-sha256` | Фиксированный алгоритм; только файл |
| `clear_dns_cache` | `true` | Очистить DNS-кэш перед бинарной копией |
| `clear_console_history` | `true` | Очистить историю консоли перед бинарной копией |
| `BackupRoot` | `backups` | Корень хранения копий |
| `UseNetFolder` | `false` | В пакетном режиме требовать отдельное монтирование |
| `MonthlyArchive` | `false` | Отключить архивацию (`false`) или задать день месяца от `1` до `28` |
| `LogLevel` | `2` | Уровень `0`, `1`, `2` или `3` |
| `MainLogPath` | Пусто | Только каталог `main.log`; пусто означает текущий `BackupRoot` |
| `Login` | Пусто | Общий логин для наследования пустыми полями DeviceList; только файл |
| `Password` | Пусто | Общий пароль для наследования пустыми полями DeviceList; только файл |

При `Language=auto` язык интерфейса и логов будет выбран по локали ОС.
Для внешнего перевода используется её двухбуквенный код языка: например, для `de_DE.UTF-8` нужен файл `de.lang` рядом со скриптом.
Если подходящего перевода нет, используется английский язык.

Для `MonthlyArchive` правило немного другое: `false`/`no`/`0`/`off` отключают архивацию, `true`/`yes`/`1`/`on` означают первое число месяца, а значения от `2` до `28` задают нужный день.

При сохранении через редактор в файл записывается
`MonthlyArchive=false` либо выбранное число.

Булевы параметры принимают значения `true`/`false`, `yes`/`no`, `1`/`0`, `on`/`off`
без учёта регистра; запись через редактор использует `true`/`false`.

Такие поля, как `IgnoreOxiAccess`, `encrypt_type`, `SshPort`, `Login` и `Password`, не отображаются в «Редакторе конфигурации».

`IgnoreOxiAccess`, `encrypt_type` и `SshPort` редактор записывает при сохранении файла.
А вот `Login` и `Password` сохраняются, только если эти строки уже присутствовали в `option.cfg`, в том числе и с пустыми значениями.


Поля `SshPort`, `Login` и `Password` могут представлять для Вас интерес, если все Ваши устройства имеют одинаковый SSH-порт и одного и того же пользователя (те же имя и пароль). В этом случае в файле `devicelist.cfg` достаточно будет всего двух значений: **имени** устройства и его **IP-адреса**. 

## Пример без очисток и чувствительного экспорта

Это пример выбранной политики, **не список заводских значений**:

```ini
Language=ru
SshPort=22
UseOxidized=false
IgnoreOxiAccess=true
OxidizedHome=
UseIdentityName=true
backup_type=both
UseIncremental=true
export_format=compact
show_sensitive=false
encrypt=
encrypt_type=aes-sha256
clear_dns_cache=false
clear_console_history=false
BackupRoot=backups
UseNetFolder=false
MonthlyArchive=false
LogLevel=2
MainLogPath=
```

Первые 19 ключей показаны в порядке канонической записи.
Имеющиеся совместимые `Login` и `Password` сохраняются после них.

Отсутствующие настройки используют встроенные значения, а не значения
из соседнего примера. Например, файл только с `Language=ru` не отключает
очистки и не меняет `show_sensitive=true`.


## Пути

```ini
BackupRoot=backups
MainLogPath=logs
```

Такая запись означает каталоги `backups` и `logs` рядом со скриптом.
Абсолютные пути сохраняют своё значение. `$HOME` и `~` не раскрываются
как переменные или домашний каталог.

Недостающий `BackupRoot` создаётся при выполнении, если позволяют права.
Корневой каталог файловой системы `/` как хранилище запрещён.
Для существующих каталогов программа не исправляет владельца и права
автоматически.

Непустой `MainLogPath` должен указывать на **уже существующий доступный
для записи каталог**. Создание самого `main.log` отложено до первой записи;
это не означает создание родительского каталога. При проблеме записи копирование
продолжается с предупреждением. Журналы устройств этим параметром не перемещаются.

## Сетевое и отдельное хранилище

`UseNetFolder=true` действует в пакетном режиме. Путь должен быть покрыт
записью монтирования, отличной от записи для `/`. Допустимо отдельное сетевое
хранилище, локальный диск или bind mount; само название опции не ограничивает
тип файловой системы.

Просто каталог на той же корневой файловой системе этого условия не выполняет.
Скрипт проверяет доступность и монтирование, но не вызывает `mount`, `umount`
или `sudo` и не переключается незаметно на локальное запасное хранилище.

## Связанные параметры

При `UseIncremental=false` скрипт не сравнивает новую резервную копию с предыдущей и сохраняет каждый новый успешно созданный и проверенный файл.
На само получение копий и месячную архивацию эта настройка не влияет.
По умолчанию `UseIncremental=true`. Если в Вашем `option.cfg` такого параметра ещё нет, сравнение остаётся включённым.

`backup_type=configuration` не использует шифрование бинарной копии
и очистки перед ней. `backup_type=binary` не использует `export_format`
и `show_sensitive`. `UseOxidized=false` не использует `OxidizedHome`.

При `UseIdentityName=true` неудачное чтение Identity не заменяется
на `--device-name` или имя из DeviceList. Для заданного имени отключите
`UseIdentityName`: [правила именования](DEVICES.md#device-names).

При `MonthlyArchive=true` архивация выполняется при запуске скрипта в выбранный день месяца
по местному времени хоста. Время запуска внутри этого дня значения не имеет.
Если в этот день скрипт не запускался, пропущенная архивация не догоняется.

Какие файлы попадают в архив, где он создаётся и как получает своё имя,
описано в [BACKUPS.md](BACKUPS.md#monthly-archive).
Период, граница данных и пропущенные попытки определены в
[BACKUPS.md](BACKUPS.md#monthly-archive).

Конфигурация может содержать секреты. Ограничьте доступ к ней и не включайте
её в публичный репозиторий: [SECURITY.md](SECURITY.md).
