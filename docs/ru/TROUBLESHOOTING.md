## С чего начать

Если резервное копирование не началось или завершилось с ошибкой, сначала смотрим журналы. В `main.log` находятся общие этапы работы, а подробности копирования конкретного устройства записываются в его отдельный журнал.

Ищем записи с отметкой `[ER]` и кодом ошибки. Расшифровка кодов приведена [ниже](#result-codes), расположение журналов описано в [LOGGING.md](LOGGING.md).

Версию установленного скрипта и справку по параметрам можно получить командами:

```bash
mikrotik-backup.sh --version
mikrotik-backup.sh --help
```

Для повторного запуска уже подготовленного пакетного копирования с подробным выводом:

```bash
mikrotik-backup.sh --log-level=3
printf 'Код завершения: %s\n' "$?"
```

Вторая команда показывает результат завершившегося запуска. Уровень журналирования в `option.cfg` при этом не меняется.

## Скрипт не начинает резервное копирование

### Вместо копирования открылся редактор

При запуске без ключей это означает, что рядом со скриптом нет `option.cfg` либо в нём нет пригодных настроек. Пустой файл, одни комментарии или неизвестные параметры ситуацию не изменят.

Откройте «Редактор конфигурации», выберите нужные настройки, сохраните файл и запустите скрипт повторно:

```bash
mikrotik-backup.sh -e
```

Сохранение устройства через мастер создаёт `devicelist.cfg`, но не заменяет подготовку `option.cfg`.

*(N.B. Если такой запуск происходит из планировщика, редактор открыть не получится, и скрипт завершится с кодом `31`. Настройки для автоматического запуска необходимо подготовить заранее.)*

### Ошибка параметров, код 12

Проверьте написание ключей, их значения и сочетание действий. Причиной могут быть неизвестный ключ, пустое значение, несколько разных действий одновременно или неполные реквизиты одиночного подключения.

Для одиночного CLI-запуска требуются адрес, логин и пароль. Недостающие реквизиты из `option.cfg` не подставляются.

Короткие параметры подключения записываются только через `=`: `-a=`, `-u=`, `-p=`. Причём `-p` задаёт пароль, а для SSH-порта используется `--port`.

Все допустимые ключи и примеры приведены в [CLI.md](CLI.md).

### Не читается option.cfg, код 21

Проверьте, что `option.cfg` является обычным файлом и доступен для чтения пользователю, от которого запускается скрипт. Допустима и читаемая символическая ссылка на такой файл.

Отсутствие файла и невозможность его прочитать являются разными ситуациями. Если файл существует, но недоступен, скрипт не продолжит работу с настройками «по умолчанию».

### Не найдена зависимость, код 30

Для проверки наличия основных утилит выполните:

```bash
command -v ssh scp sshpass timeout sleep sha256sum realpath flock
```

При пакетной работе с `UseNetFolder=true` также нужен `findmnt`. В день месячной архивации требуются `zip`, `unzip` и GNU `mv`. Для копирования консольной команды из мастера нужен GNU `base64` с поддержкой `--wrap=0`.

**Одного наличия утилиты недостаточно.** Установленный OpenSSH должен поддерживать используемые параметры и `scp -O`, а GNU `timeout` должен поддерживать `--signal` и `--kill-after`.

Полный перечень зависимостей и команды установки находятся в [INSTALL.md](INSTALL.md#зависимости).

### Не открывается меню, код 31

Меню, редактор и мастер требуют терминал и работающую утилиту `stty`. Не запускайте их через канал или с перенаправлением стандартного ввода либо вывода.

Если сообщение указывает на недостаточный размер терминала, увеличьте окно. Основным экранам нужна ширина не менее 46 колонок, встроенной инструкции 80. В редакторе и мастере длинный список прокручивается стрелками, помещать всю форму на экран сразу не требуется.

Управление интерфейсом описано в [INTERACTIVE.md](INTERACTIVE.md).

## Не загружается список устройств

### Файл devicelist.cfg, коды 22 и 23

Проверьте расположение файла и доступ к нему. `devicelist.cfg` должен находиться рядом с `mikrotik-backup.sh`, независимо от того, из какого каталога Вы запускаете скрипт.

Поля разделяются настоящей табуляцией, а не пробелами. Для устройства должны быть определены имя, адрес, логин, пароль и допустимый SSH-порт. Общие реквизиты могут браться из `option.cfg`, если соответствующие поля записи оставлены пустыми.

Некорректная запись пропускается с предупреждением. Если пригодных устройств не осталось, копировать будет нечего, и скрипт завершится с ошибкой списка.

Также проверьте повторные подключения и одинаковые имена разных устройств. Формат файла, наследование реквизитов и правила обработки повторов разобраны в [DEVICES.md](DEVICES.md).

### Импорт из Oxidized, коды 24 и 25

Код `24` означает проблему чтения файлов `config` или `router.db` из каталога `OxidizedHome`. Код `25` относится к их содержимому: неподдерживаемой схеме, ошибочным данным или отсутствию пригодных устройств MikroTik.

Проверьте путь, доступ к обоим файлам, источник `csv`, разделитель, карту столбцов и определение модели `routeros`. Данные читаются именно из `<OxidizedHome>/router.db`; параметр Oxidized `source.csv.file` этот путь не меняет.

При `IgnoreOxiAccess=true` скрипт может продолжить работу по прежнему пригодному списку. Но ошибка импорта всё равно останется в результате запуска. При `false` старый список для такого запуска не используется.

Настройка импорта описана в [DEVICES.md](DEVICES.md#импорт-из-oxidized).

## Хранилище и блокировки

### Блокировка занята, код 32

Проверьте, не работает ли уже другое задание с тем же каталогом резервных копий. Для запусков от одного пользователя пакетное копирование конфликтует с любым другим копированием в тот же `BackupRoot`. Два одиночных запуска для одного устройства также не могут выполняться одновременно в этом хранилище.

Дождитесь завершения работающего задания и повторите запуск.

**Не удаляйте файлы блокировок, чтобы «освободить» хранилище.** Они остаются после завершения скрипта, а сама блокировка удерживается процессом. Наличие файла в `/tmp/mikrotik-backup-${UID}/` ещё не означает, что блокировка занята.

### Нет доступа к каталогу

Проверьте путь `BackupRoot`, права пользователя, свободное место и доступность самого накопителя. Относительный путь считается от каталога скрипта. Корневой каталог файловой системы `/` использовать для хранения копий нельзя.

Если раньше скрипт запускался от root, а теперь работает от **bsmt**, прежние каталоги и файлы могут быть ему недоступны. Подготовка прав уже разобрана в [INSTALL.md](INSTALL.md#автоматический-запуск-скрипта).

Для пакетной работы с `UseNetFolder=true` требуется отдельное монтирование. Проверить его можно так:

```bash
findmnt -T /mnt/backup/mikrotik
findmnt -T /
```

Первый путь замените своим. Если оба пути относятся к одной и той же записи монтирования, обычный каталог на корневой файловой системе требование `UseNetFolder=true` не выполняет. Сам скрипт хранилище не монтирует.

Код `64` означает ошибку каталога устройства или его архива при доступном общем хранилище. Остальные устройства могут обрабатываться дальше. Код `65` означает потерю или нарушение состояния общего хранилища и останавливает оставшуюся пакетную обработку.

Правила сетевого хранилища описаны в [OPTIONS.md](OPTIONS.md#network-storage).

## Ошибки при работе с устройством

### SSH и передача файлов, коды 40–43

Проверьте адрес устройства, доступность его SSH-службы, логин, пароль и порт. Если порт в `devicelist.cfg` не указан, используется `SshPort` из настроек, по умолчанию `22`.

Пользователь RouterOS должен иметь права на выбранные операции: экспорт конфигурации, создание и получение копий, удаление временных файлов и включённые очистки.

**И тут есть нюанс!!!** Успешное подключение привычной командой SSH ещё не означает, что скрипт использует те же настройки. Он работает по паролю, не использует SSH-агент, ключи и обычный `~/.ssh/config`. Получение файлов выполняется через `scp -O`.

Код `40` относится к соединению или работе транспортного канала, `41` к аутентификации, `42` к команде RouterOS или её ответу, `43` к передаче файла. Подробнее о параметрах подключения в [SECURITY.md](SECURITY.md#подключение-к-routeros).

### Ошибка имени, коды 50 и 52

Код `50` означает, что итоговое имя устройства непригодно. Проверьте выбранный источник имени и содержимое скобок: в текущей версии именно первый завершённый непустой фрагмент в круглых скобках используется для имени.

После обработки длина должна составлять от 1 до 32 символов. Слишком длинное имя не обрезается. Зарезервированные имена вроде `CON` и `NUL` также не допускаются.

Код `52` означает совпадение итогового имени с другим устройством в этом запуске. Регистр при сравнении не учитывается: `Router-A` и `router-a` считаются одинаковыми.

Источник имени и правила его обработки описаны в [DEVICES.md](DEVICES.md#device-names).

### Не прошла проверка копии, коды 51 и 53

Код `51` относится к `.rsc`, код `53` к `.backup`. Полученный файл не прошёл проверку: например, он пустой или его размер не совпал с размером файла на устройстве.

Посмотрите, на каком этапе возникла ошибка, проверьте свободное место и права как на хосте, так и на RouterOS. После неудачной попытки скрипт делает ещё одну через 2 секунды. Для двух форматов попытки выполняются отдельно, поэтому один файл может быть получен успешно, а второй нет.

Предупреждение об удалении временного файла с RouterOS после успешного получения копии само по себе не означает, что локальная копия повреждена.

## Новой копии нет, но ошибок тоже нет

Сначала проверьте `UseIncremental`. При включённом сравнении новая копия может быть удалена как повторная, а предыдущая останется. Для `.rsc` сравнивается содержимое без даты стандартного заголовка, для `.backup` только размер файлов.

При `UseIncremental=false` новая исправная копия сохраняется без этого сравнения.

Также учитывайте, что два запуска для одного устройства в тот же каталог в течение одной минуты используют одинаковое имя файла. Отдельная версия для второго запуска не создаётся.

Если в этот день выполнялась месячная архивация, проверьте и ZIP. В одиночном CLI-режиме новая копия тоже может оказаться внутри него. Полные правила хранения приведены в [BACKUPS.md](BACKUPS.md).

<a id="archive-problems"></a>
## Месячный архив не появился

Проверьте значение `MonthlyArchive` и дату запуска по местному времени хоста. Значение `false` отключает архивацию, `true` или `1` выбирает первое число, а число от `2` до `28` задаёт нужный день месяца.

В выбранный день время запуска значения не имеет. Если этот день был пропущен, следующий обычный запуск его не догоняет. При работе через «Мастер резервного копирования» месячная архивация не выполняется.

Если архивировать нечего, пустой ZIP не создаётся.

### Где искать ZIP

Имя архива соответствует предыдущему календарному дню. Например, при запуске 1 октября 2026 года это `30.09.2026.zip`:

| Режим | Расположение |
|---|---|
| Пакетный | `<BackupRoot>/<DeviceName>/archive/30.09.2026.zip` |
| Одиночный через CLI | `<BackupRoot>/30.09.2026.zip` |

Каталог `archive/` пишется строчными буквами. При повторном запуске в тот же день обновляется ZIP с тем же именем.

### Архивирование завершилось с ошибкой

При кодах `70` и `71` проверьте журнал устройства, доступ к каталогу архивов, свободное место и состояние уже существующего ZIP. Для работы требуется место и в хранилище, и в локальном `/tmp`.

На локальном диске каталог `archive/` должен принадлежать пользователю скрипта и иметь права `0700`. При пакетной работе с проверенным сетевым хранилищем и `UseNetFolder=true` отличающиеся владелец и права, назначенные NAS, сами по себе не являются причиной отказа. Ошибки хранилища при архивации также могут давать `64` или `65`.

Проверить существующий архив можно командой, указав его фактический путь:

```bash
unzip -t "/mnt/backup/mikrotik/Router-A/archive/30.09.2026.zip"
```

До сохранения проверенного ZIP исходные файлы не удаляются. Если архив уже сохранён, но удалить часть исходников не удалось, останутся и ZIP, и неудалённые файлы. Повреждённый существующий архив автоматически не заменяется новым.

**Не удаляйте оставшиеся копии и журналы, пока не проверили содержимое архива.** Порядок архивирования описан в [BACKUPS.md](BACKUPS.md#monthly-archive).

<br />

## Нет журнала или вывода на экран

При `LogLevel=0` и отсутствии ошибок новые журналы не создаются. В остальных случаях проверьте выбранные `BackupRoot`, `MainLogPath` и права записи.

Пустой `MainLogPath=` оставляет `main.log` в `BackupRoot`. Если задан отдельный каталог, он должен уже существовать и быть доступен пользователю скрипта. Журналы устройств этим параметром не перемещаются.

После месячной архивации прежняя история устройства находится в ZIP. Последующая работа записывается в новый журнал рядом с копиями.

При запуске из планировщика или с перенаправлением вывода экранный журнал с индикатором и цветными отметками отсутствует. Файловые журналы от этого не отключаются.

Ошибка записи журнала не останавливает само копирование, но отражается в результате запуска как предупреждение. Подробнее в [LOGGING.md](LOGGING.md).

<a id="language-problems"></a>
## Перевод не применился

Проверьте выбранный язык и расположение файла. Например, для `Language=de` нужен читаемый обычный файл `de.lang` рядом с `mikrotik-backup.sh`, а не в каталоге `lang/`. Символическая ссылка для файла перевода не используется.

При `Language=auto` язык определяется по окружению ОС. На один запуск его можно указать явно, например при просмотре справки:

```bash
mikrotik-backup.sh --language=de --help
```

Непереведённые сообщения выводятся по-английски. Некорректные строки файла пропускаются. Файлы `ru.lang` и `en.lang` встроенные переводы не заменяют.

Формат строк, имена ключей и правила подключения описаны в [LOCALIZATION.md](LOCALIZATION.md).

<br />

## Настройка не применяется

Проверьте имя параметра, допустимое значение и повторные записи в `option.cfg`. При повторе используется последнее пригодное значение. Регистр ключей не важен, но дефис и подчёркивание не взаимозаменяемы.

Параметр, переданный через CLI, заменяет соответствующее значение из файла. Для обычных одиночного и пакетного запусков порядок такой:

**Встроенные значения** → **Пригодные строки option.cfg** → **CLI**

У «Мастера резервного копирования» свой порядок заполнения формы: обычные поля берутся из встроенных значений и CLI, а не из файла опций. Исключение составляет `UseIncremental`. Настройки журналирования из файла при выполнении через мастер также учитываются.

Правила чтения параметров приведены в [OPTIONS.md](OPTIONS.md), особенности мастера в [INTERACTIVE.md](INTERACTIVE.md).

|---:|---|

| `1` | Завершение с предупреждениями, без сохранённой ошибки выполнения |

| `33` | Неподходящий путь или объект хранилища одиночного запуска |

| `65` | Потеря или нарушение состояния общего хранилища во время работы; пакетная обработка останавливается |
| `70` | Ошибка создания или обновления архива |
| `71` | ZIP или целевой архивный объект не прошёл проверку |
| `80` | Внутренняя ошибка или невыполненное системное требование, в том числе возможности `C.UTF-8` |
| `81` | Ошибка встроенного драйвера MikroTik |
| `129` | Завершение по сигналу HUP |
| `130` | Завершение по сигналу INT, например при нажатии Ctrl+C |
| `143` | Завершение по сигналу TERM |

Итоговый код отражает первую сохранённую ошибку выполнения. Предупреждение `1` заменяется первой такой ошибкой, а последующий успех её не отменяет. Поэтому итоговый код не обязательно совпадает с последним сообщением в журнале.

Если повторная попытка получения файла прошла успешно, этап может завершиться с `[OK]`, хотя ошибка первой попытки останется в журнале. Ненулевой итог пакетного запуска также не означает, что не удалось скопировать все устройства: результаты смотрим по каждому отдельно.

При коде `80` обратите внимание на системные требования: GNU Bash не ниже 4.4 и работающую локаль `C.UTF-8`. Подробности приведены в [INSTALL.md](INSTALL.md#требования-к-хосту).

## Если нужна помощь

Укажите версию скрипта, ОС и Bash, способ запуска, код завершения и приложите относящийся к ошибке фрагмент журнала. Для проблемы одного устройства нужен его журнал, для ошибки подготовки запуска прежде всего `main.log`.

**Не присылайте реальные пароли и рабочие файлы настроек целиком.** Перед отправкой проверьте журналы, снимки экрана и команды на наличие закрытых данных. Особенности защиты паролей разобраны в [SECURITY.md](SECURITY.md).

Связаться с автором можно через контакты в [описании продукта](../README_RU.md#связаться-с-автором).
