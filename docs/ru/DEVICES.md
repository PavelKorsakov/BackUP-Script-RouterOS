# Список устройств

[Оглавление](../README_RU.md)

## Перечень устройств для резервного копирования, или файл devicelist.cfg
Как ясно из названия, в файле `devicelist.cfg` перечисляются устройства для пакетного копирования и данные для подключения к ним. 
Сам файл следует разместить непосредственно рядом со скриптом `mikrotik-backup.sh`.  
Создать `devicelist.cfg` можно как вручную, так и с помощью «Мастера резервного копирования».
Третий вариант будет полезен, если Вы на этом же сервере используете сервис Oxidized. Тогда после внесения соответствующих настроек в файл опций
скрипт будет динамически создавать перечень устройств в файле `devicelist.cfg` каждый раз при запуске, вытаскивая из конфигурационных файлов Oxidized все необходимые данные.

<br />

## Создание и редактирование списка

Для создания списка через «Мастер резервного копирования» запустите:

```bash
mikrotik-backup.sh -b
```

Заполняем имя устройства, адрес, логин, пароль и SSH-порт → выбираем «2. Сохранить устройство в devicelist.cfg».  
Мастер либо создаст файл с нужной записью, либо добавит или обновит запись в существующем файле.

Готовый список можно править обычным текстовым редактором. Сам мастер существующие записи в свою форму не загружает.

*(N.B. При сохранении из мастера порт `22` записывается пустым полем. При пакетном копировании для такой записи будет использован `SshPort` из настроек скрипта. Нестандартный порт сохраняется явно.)*

<br />

## Формат файла

Каждое устройство записывается отдельной строкой. Поля разделяются **табуляцией (TAB)**, а не пробелами. Порядок полей следующий:

| Позиция | Поле | Назначение |
|---|---|---|
| 1 | Имя | Имя устройства; обязательно |
| 2 | Адрес | IP-адрес или DNS-имя устройства; обязательно |
| 3 | Логин | Пользователь устройства RouterOS; если не указан, берётся из `Login` в `option.cfg` |
| 4 | Пароль | Пароль устройства RouterOS; если не указан, берётся из `Password` в `option.cfg` |
| 5 | Порт | SSH-порт от `1` до `65535`; если не указан, берётся из `SshPort`, по умолчанию `22` |
| 6 | Маркер устройства | `MikroTik`; можно не заполнять. Регистр не важен |

Поля начиная с седьмого не используются. Записи с другим маркером устройства пропускаются.

### Пример списка

В примере между полями стоят настоящие символы TAB:

```text
Router-A	xxx.xxx.xxx.1	UserName	MySuperPassword	1922	MikroTik
Router-B	xxx.xxx.xxx.2	UserName	MySuperPassword		MikroTik
```
Во второй строке порт не указан: между паролем и `MikroTik` стоят две табуляции. Адреса и учётные данные замените своими.

### Общие логин, пароль и порт

Если все Ваши устройства используют одинаковые реквизиты, их можно указать один раз в `option.cfg`:

```ini
Login=UserName
Password=MySuperPassword
SshPort=22
```

Тогда в `devicelist.cfg` достаточно имени и адреса каждого устройства:

```text
Router-A	xxx.xxx.xxx.1
Router-B	xxx.xxx.xxx.2
```

Собственные реквизиты устройства, указанные в его строке, заменяют общие значения.

*(N.B. Файл списка содержит пароли. Ограничьте доступ к нему, как описано в [SECURITY.md](SECURITY.md).)*

## Как читается список

Пустые строки и строки с первым непробельным `#` игнорируются. Комментарии пишутся отдельно; `#` внутри поля является частью его значения.

В имени, адресе, порте и маркере внешние пробелы удаляются. Логин и пароль читаются буквально, вместе с пробелами и кавычками. Файлы с окончаниями строк Windows (CRLF) поддерживаются.

Если в какой-либо строке (записи об устройстве) будет допущено нарушение установленного синтаксиса, такая строка во время выполнения скрипта
будет пропущена, но будет выведено предупреждение о некорректности этой записи.

Если какая-то строка в силу каких-либо причин будет продублирована, т. е. будет обнаружено совпадение четырёх параметров (**адреса, логина, пароля и порта**), подключение к такому устройству выполняется только один раз, с данными последней записи. 
Если у разных подключений совпадает имя, используется первая пригодная запись, а конфликтующая пропускается.

## Имена устройств

Имя используется в названиях резервных копий, а в пакетном режиме ещё и для подкаталога устройства. 
Откуда его брать, определяет настройка `UseIdentityName` в файле опций `option.cfg`:

| Значение | Источник имени |
|---|---|
| `true` (по умолчанию) | Параметр Identity на самом устройстве RouterOS |
| `false` | Имя из `devicelist.cfg`, поля мастера или ключа `--device-name` при одиночном CLI-запуске |


### Имя в скобках

Если в исходном имени есть круглые скобки, скрипт использует содержимое первой завершённой непустой группы. Если такой группы нет, используется всё имя.

| Исходное имя | Имя для резервных копий |
|---|---|
| `Филиал (Core East)` | `Core_East` |
| `Branch () (Core)` | `Core` |
| `Филиал (Core (East) West)` | `Core_East_West` |

### Допустимые символы

В итоговом имени сохраняются буквы, включая кириллицу, цифры, точки, дефисы и подчёркивания. Пробелы и недопустимые символы заменяются на `_`. Повторные и крайние подчёркивания убираются, как и ведущие точки и дефисы, а также точки в конце имени.

Например, `ЦОД Москва №1` станет `ЦОД_Москва_1`.

Длина итогового имени должна составлять **от 1 до 32 символов**. Слишком длинное имя не обрезается, а вызывает ошибку. Зарезервированные имена `CON`, `PRN`, `AUX`, `NUL`, `COM1`–`COM9`, `LPT1`–`LPT9` не допускаются.

Итоговые имена должны быть уникальны без учёта регистра: `Router-A` и `router-a` считаются одинаковыми. Второе устройство с таким именем в этом запуске будет пропущено.

*(N.B. При изменении итогового имени меняется и подкаталог устройства. Старые копии автоматически не переносятся.)*

## Импорт из Oxidized

Если Вы уже ведёте список устройств в Oxidized, скрипт может получать его оттуда. Для этого укажите в `option.cfg`:

```ini
UseOxidized=true
OxidizedHome=/var/lib/oxidized
IgnoreOxiAccess=true
```

В `OxidizedHome` укажите каталог с файлами `config` и `router.db`. Из них формируется `devicelist.cfg`. Сами файлы Oxidized не изменяются.

*(N.B. Импорт заменяет `devicelist.cfg`, а не дополняет его. Ручные добавления в этот файл при следующем успешном обновлении из Oxidized будут потеряны.)*

### Настройки источника

В конфигурации Oxidized должен использоваться источник `csv` с разделителем из одного символа. Порядок столбцов определяется картой `source.csv.map`, нумерация начинается с нуля:

| Поле карты | Что используется |
|---|---|
| `name` | Имя устройства; обязательный столбец |
| `ip` | Адрес устройства; если не указан, используется значение `name` |
| `username` | Логин; если не указан, используется общий `Login` из `option.cfg` |
| `password` | Пароль; если не указан, используется общий `Password` из `option.cfg` |
| `port` | SSH-порт; если не указан, используется `SshPort` |
| `model` | Модель устройства; если столбца нет, используется корневой параметр `model` |

Учитываются правила `model_map` до первого совпадения. Импортируются только устройства с итоговой моделью `routeros`. Если столбец `model` есть, корневой параметр не заменяет его пустые значения.

Данные всегда читаются из `<OxidizedHome>/router.db`. Параметр Oxidized `source.csv.file` этот путь не меняет.

### Если импорт не удался

Если файлы Oxidized недоступны, их формат не поддерживается или подходящих устройств нет, прежний `devicelist.cfg` сохраняется.

При `IgnoreOxiAccess=true` скрипт сможет использовать прежний пригодный список. При `false` копирование по старому списку не выполняется.

Ошибка импорта отражается в результате запуска, даже если копирование по прежнему списку прошло успешно.

Подробнее об ошибках списка и импорта: [Диагностика](TROUBLESHOOTING.md).
