# Командная строка

[Оглавление](../README_RU.md)

## Синтаксис

```text
mikrotik-backup.sh [действие] [параметры]
```

Параметры, указываемые в командной строке, могут быть как длинные: `--параметр значение` или `--параметр=значение`.  
Так и короткие: `-п=значение`. Но если **значение** начинается с `-`, используется только форма с `=`, т.е. `--параметр=-значение`.

Неизвестный параметр, позиционный аргумент, пропущенное, явно пустое или недопустимое значение при работе скрипта вызовет код ошибки (12), и работа скрипта будет остановлена.

<br />

## Действия

| Действие | Назначение |
|---|---|
| `-i` | Основное интерактивное меню |
| `-b` | Мастер резервного копирования  |
| `-e` | Редактор конфигурации (option.cfg) |
| `-h`, `--help` | Справка по ключам CLI |
| `-v`, `--version` | Версия скрипта |

Скрипт запрещает указание нескольких ключей Действия подряд, например одновременно: `mikrotik-backup.sh -i -b` приведет к остановке скрипта и вызовет код ошибки (12).

<br />

## Параметры

| Параметр | Значение | Назначение |
|---|---|---|
| `--device-name` | Имя | Имя устройства при `UseIdentityName=false` |
| `--address` | Адрес или DNS-имя | Адрес устройства RouterOS |
| `--user` | Логин | Пользователь устройства RouterOS |
| `--password` | Пароль | Пароль устройства RouterOS |
| `--port` | `1`–`65535` | SSH-порт устройства; по умолчанию `22` |
| `--language` | `auto` или две ASCII-буквы | Язык текущего интерфейса и логов скрипта |
| `--use-oxidized` | Булево значение* | Импорт списка из Oxidized |
| `--oxidized-home` | Путь | Каталог настроек oxidized; его `config` и `router.db` |
| `--use-identity-name` | Булево значение* | Получать имя из параметра Identity RouterOS |
| `--backup-root` | Путь | Корень хранения копий |
| `--use-net-folder` | Булево значение* | В пакетном режиме проверять монтирование |
| `--monthly-archive` | `false` или число `1`–`28`* | Разрешить ежемесячную архивацию по календарю |
| `--log-level` | `0`, `1`, `2`, `3` | Подробность журналов и терминального вывода |
| `--main-log-path` | Путь | Только каталог для `main.log` |
| `--backup-type` | `configuration`,`binary`,`both` | Какие форматы получать |
| `--export-format` | `compact`, `terse`, `verbose` | Формат текстового экспорта |
| `--show-sensitive` | Булево значение* | Включать чувствительные значения в экспорт |
| `--encrypt` | Непустой пароль | Шифрование `.backup` алгоритмом AES-SHA256 |
| `--clear-dns-cache` | Булево значение* | Очистка DNS-кэша перед бинарной копией |
| `--clear-console-history` | Булево значение* | Очистка истории консоли перед бинарной копией |

`*` Булевы значения: `true` или `false`; но скрипт также понимает и `yes`/`no`, `1`/`0`, `on`/`off` без учёта регистра.  
Для `backup-type` также принимаются `config` и `conf` как синонимы `configuration`.

Короткие формы подключения:

```text
-a=VALUE    соответствует --address VALUE
-u=VALUE    соответствует --user VALUE
-p=VALUE    соответствует --password VALUE
```

## Режим запуска скрипта через командную строку
Скрипт позволяет запустить резервное копирование единичного устройства, но для этого ему требуется минимум три параметра для запуска.
Это **IP адрес устройства**, **логин** и **пароль**. т.е. строка запуска: 
```bash
mikrotik-backup.sh --address=xxx.xxx.xxx.xxx --user=UserName --password=MySuperPassword
```
Уже пригодна для использования. Все прочие, указанные выше, параметры тут будут опциональны.  
*(N.B. Очень важная ремарка - скрипт НЕ предназначен для запуска тройки вместе с ключами **Действия**.)*

**Нюанс!!!**  
При одиночном запуске все три параметра подключения должны быть указаны через CLI. Скрипт не возьмёт недостающий логин или пароль из `option.cfg`.

<br />

## Приоритет настроек

Для обычного одиночного и пакетного копирования действует тот же порядок, что описан в [OPTIONS.md](OPTIONS.md):  
**Встроенные значения** → **Пригодные строки option.cfg** → **CLI**

То есть если параметр уже указан в `option.cfg`, но для конкретного запуска Вам нужно другое значение, укажите его через CLI. Переписывать файл настроек для этого не требуется.

При одиночном запуске список устройств и импорт из Oxidized не используются. Но остальные настройки из `option.cfg` продолжают действовать, если Вы не заменили их параметрами командной строки.

**У "Мастера резервного копирования" свой порядок заполнения формы.**  
Обычные поля берутся из встроенных значений и переданных CLI-параметров, а не из `option.cfg`. Исключение составляет `UseIncremental`: эта настройка наследуется из файла либо получает значение по умолчанию.  
При выполнении сохраняются выбранные для запуска `LogLevel` и `MainLogPath`, а месячная архивация отключена. Подробности работы самого мастера описаны в [INTERACTIVE.md](INTERACTIVE.md).

## Параметры командной строки по назначению

### Подключение и имя устройства

| Ключ | Значение | Назначение |
|---|---|---|
| `--address` | IP-адрес или DNS-имя | Адрес устройства RouterOS |
| `--user` | Логин | Пользователь устройства RouterOS |
| `--password` | Пароль | Пароль устройства RouterOS |
| `--port` | От `1` до `65535` | SSH-порт устройства; по умолчанию `22` |
| `--device-name` | Имя | Имя устройства при `UseIdentityName=false` |
| `--use-identity-name` | `true` / `false` | Получать имя из параметра Identity RouterOS |

Чтобы использовать своё имя, укажите одновременно `--use-identity-name false` и `--device-name ИМЯ`.

<br />

### Формат и содержимое резервных копий

| Ключ | Значение | Назначение |
|---|---|---|
| `--backup-type` | `configuration`, `binary`, `both` | Какие форматы получать |
| `--export-format` | `compact`, `terse`, `verbose` | Формат текстового экспорта |
| `--show-sensitive` | `true` / `false` | Включать чувствительные значения в экспорт |
| `--encrypt` | Непустой пароль | Шифрование `.backup` алгоритмом AES-SHA256 |
| `--clear-dns-cache` | `true` / `false` | Очистка DNS-кэша перед бинарной копией |
| `--clear-console-history` | `true` / `false` | Очистка истории консоли перед бинарной копией |

Для `--backup-type` значения `config` и `conf` также означают `configuration`.

*(N.B. Для `UseIncremental` отдельного CLI-ключа нет. Эта настройка задаётся в `option.cfg`, «Редакторе конфигурации» или BackUP Master. Её назначение описано в [OPTIONS.md](OPTIONS.md).)*

<br />

### Хранилище, архивация и журналы

| Ключ | Значение | Назначение |
|---|---|---|
| `--backup-root` | Путь | Корень хранения копий |
| `--use-net-folder` | `true` / `false` | В пакетном режиме проверять монтирование |
| `--monthly-archive` | `false` или число от `1` до `28` | Разрешить ежемесячную архивацию по календарю |
| `--log-level` | `0`, `1`, `2`, `3` | Подробность журналов и терминального вывода |
| `--main-log-path` | Путь к каталогу | Только каталог для `main.log` |

Для `--monthly-archive` действует отдельное правило: `true`/`yes`/`1`/`on` означают первое число месяца, `false`/`no`/`0`/`off` отключают архивацию. Значения от `2` до `28` задают нужный день.

Ключ выбирает день архивации, а не запускает её немедленно. Правила этого режима описаны в [BACKUPS.md](BACKUPS.md#monthly-archive).

Для `--main-log-path` указывается каталог, а не полный путь с именем `main.log`. На журналы устройств эта настройка не влияет.

<br />

### Источник списка устройств и язык

| Ключ | Значение | Назначение |
|---|---|---|
| `--use-oxidized` | `true` / `false` | Импорт списка из Oxidized |
| `--oxidized-home` | Путь | Каталог настроек oxidized; его `config` и `router.db` |
| `--language` | `auto` или двухбуквенный код | Язык текущего интерфейса и логов скрипта |

При `--language auto` язык выбирается по локали ОС. Можно указать его явно, например `ru`, `en` или `de`. Для русского и английского отдельный файл перевода не нужен; остальные переводы подключаются из файлов рядом со скриптом. Если подходящего перевода нет, используется английский язык.  
Подробнее: [LOCALIZATION.md](LOCALIZATION.md).

## Примеры запуска

**Обратите внимание!!!**  
По умолчанию включены чувствительный экспорт, очистка DNS-кэша и очистка истории консоли перед бинарной копией. В одиночных примерах ниже выбрана работа без очисток и чувствительного экспорта.

*(N.B. Пароли, указанные через CLI, могут быть видны в истории оболочки и аргументах процессов. Это касается и пароля шифрования `.backup`, который также может быть виден в аргументах дочернего `ssh`. Подробности: [SECURITY.md](SECURITY.md).)*

### Только конфигурация `.rsc`, без чувствительных данных

```bash
mikrotik-backup.sh --address=xxx.xxx.xxx.xxx --user=UserName --password=MySuperPassword --backup-type=configuration --show-sensitive=false
```

### Оба формата, своё имя устройства, без очисток

```bash
mikrotik-backup.sh --address=xxx.xxx.xxx.xxx --user=UserName --password=MySuperPassword --use-identity-name=false --device-name=edge-router --backup-type=both --show-sensitive=false --clear-dns-cache=false --clear-console-history=false
```

### Бинарная копия с шифрованием

```bash
mikrotik-backup.sh --address=xxx.xxx.xxx.xxx --user=UserName --password=MySuperPassword --backup-type=binary --encrypt='ПАРОЛЬ_ШИФРОВАНИЯ' --clear-dns-cache=false --clear-console-history=false
```

### Пакетный запуск с отдельным каталогом и подробным журналом

Здесь подразумевается, что `option.cfg` и список устройств уже подготовлены:

```bash
mikrotik-backup.sh --backup-root=/srv/mikrotik-backups --log-level=3
```

Остальные настройки для этого пакетного запуска берутся из `option.cfg` и встроенных значений.

## Если команда не принята

Неизвестный ключ, лишний позиционный аргумент, пропущенное или недопустимое значение приводят к ошибке `12`. Резервное копирование при этом не начинается. Проверить написание ключей можно через `-h`.

**Пустые значения через CLI не передаются.**  
Записи `--encrypt=''` и `--main-log-path=''` будут отклонены. Пустые значения `encrypt=` и `MainLogPath=` задаются в `option.cfg` или через «Редактор конфигурации».

Коды завершения и их значения описаны в разделе [Диагностика](TROUBLESHOOTING.md#result-codes).
