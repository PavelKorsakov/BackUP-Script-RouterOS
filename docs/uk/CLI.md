# Командний рядок

[Зміст](../README_UK.md)

## Синтаксис

```text
mikrotik-backup.sh [дія] [параметри]
```

Параметри командного рядка можуть мати довгу форму: `--параметр значення` або `--параметр=значення`.
Також є коротка форма: `-п=значення`. Однак якщо **значення** починається з `-`, дозволено лише форму з `=`, тобто `--параметр=-значення`.

Невідомий параметр, позиційний аргумент, пропущене, явно порожнє або неприпустиме значення спричиняють помилку `12` і зупиняють скрипт.

<br />

## Дії

| Дія | Призначення |
|---|---|
| `-i` | Головне інтерактивне меню |
| `-b` | BackUP Master |
| `-e` | Configuration Editor (`option.cfg`) |
| `-h`, `--help` | Довідка щодо параметрів CLI |
| `-v`, `--version` | Версія скрипта |

Не можна вказувати кілька параметрів дії одночасно. Наприклад, `mikrotik-backup.sh -i -b` зупинить скрипт із помилкою `12`.

<br />

## Параметри

| Параметр | Значення | Призначення |
|---|---|---|
| `--device-name` | Ім’я | Ім’я пристрою за `UseIdentityName=false` |
| `--address` | Адреса або DNS-ім’я | Адреса пристрою RouterOS |
| `--user` | Логін | Користувач пристрою RouterOS |
| `--password` | Пароль | Пароль пристрою RouterOS |
| `--port` | `1`–`65535` | SSH-порт пристрою; стандартне значення `22` |
| `--language` | `auto` або дві ASCII-літери | Мова поточного інтерфейсу й журналів скрипта |
| `--use-oxidized` | Логічне значення* | Імпортувати список з Oxidized |
| `--oxidized-home` | Шлях | Каталог налаштувань Oxidized із `config` і `router.db` |
| `--use-identity-name` | Логічне значення* | Отримувати ім’я з RouterOS Identity |
| `--backup-root` | Шлях | Кореневий каталог сховища копій |
| `--use-net-folder` | Логічне значення* | Перевіряти монтування в пакетному режимі |
| `--monthly-archive` | `false` або число `1`–`28`* | Увімкнути календарне щомісячне архівування |
| `--log-level` | `0`, `1`, `2`, `3` | Докладність журналів і виведення в термінал |
| `--main-log-path` | Шлях | Лише каталог для `main.log` |
| `--backup-type` | `configuration`,`binary`,`both` | Формати, які потрібно отримати |
| `--export-format` | `compact`, `terse`, `verbose` | Формат текстового експорту |
| `--show-sensitive` | Логічне значення* | Додавати чутливі значення до експорту |
| `--encrypt` | Непорожній пароль | Шифрувати `.backup` алгоритмом AES-SHA256 |
| `--clear-dns-cache` | Логічне значення* | Очистити DNS-кеш перед бінарною копією |
| `--clear-console-history` | Логічне значення* | Очистити історію консолі перед бінарною копією |

`*` Логічні значення — `true` або `false`; скрипт також приймає `yes`/`no`, `1`/`0` і `on`/`off` без урахування регістру.
Для `backup-type` також приймаються `config` і `conf` як синоніми `configuration`.

Короткі форми підключення:

```text
-a=VALUE    те саме, що --address VALUE
-u=VALUE    те саме, що --user VALUE
-p=VALUE    те саме, що --password VALUE
```

## Запуск скрипта з командного рядка

Скрипт може створити резервну копію одного пристрою, але для такого запуску потрібні щонайменше три параметри: **IP-адреса пристрою**, **логін** і **пароль**. Отже, ця команда вже придатна для використання:

```bash
mikrotik-backup.sh --address=xxx.xxx.xxx.xxx --user=UserName --password=MySuperPassword
```

Усі інші наведені вище параметри тут необов’язкові.
*(N.B. Дуже важливе зауваження: скрипт НЕ призначений для поєднання цієї трійки з параметрами **Дії**.)*

**Нюанс!!!**
Для запуску одного пристрою всі три параметри підключення потрібно передати через CLI. Скрипт не візьме відсутній логін або пароль із `option.cfg`.

<br />

## Пріоритет налаштувань

Для звичайного запуску одного пристрою та пакетного копіювання діє порядок, описаний у [OPTIONS.md](OPTIONS.md):
**Вбудовані значення** → **Придатні рядки option.cfg** → **CLI**

Якщо параметр уже є в `option.cfg`, але для певного запуску потрібне інше значення, передайте його через CLI. Перезаписувати файл налаштувань не потрібно.

Під час запуску одного пристрою список пристроїв та імпорт з Oxidized не використовуються. Інші налаштування з `option.cfg` продовжують діяти, якщо їх не замінили параметри командного рядка.

**BackUP Master має власний порядок заповнення форми.**
Звичайні поля беруть значення з вбудованих налаштувань і переданих параметрів CLI, а не з `option.cfg`. Виняток — `UseIncremental`: це налаштування успадковується з файла або отримує стандартне значення.
Під час виконання зберігаються вибрані для запуску `LogLevel` і `MainLogPath`, а щомісячне архівування вимикається. Докладніше роботу BackUP Master описано в [INTERACTIVE.md](INTERACTIVE.md).

## Параметри командного рядка за призначенням

### Підключення та ім’я пристрою

| Параметр | Значення | Призначення |
|---|---|---|
| `--address` | IP-адреса або DNS-ім’я | Адреса пристрою RouterOS |
| `--user` | Логін | Користувач пристрою RouterOS |
| `--password` | Пароль | Пароль пристрою RouterOS |
| `--port` | Від `1` до `65535` | SSH-порт пристрою; стандартне значення `22` |
| `--device-name` | Ім’я | Ім’я пристрою за `UseIdentityName=false` |
| `--use-identity-name` | `true` / `false` | Отримувати ім’я з RouterOS Identity |

Щоб використати власне ім’я, укажіть одночасно `--use-identity-name false` і `--device-name ІМ’Я`.

<br />

### Формат і вміст резервних копій

| Параметр | Значення | Призначення |
|---|---|---|
| `--backup-type` | `configuration`, `binary`, `both` | Формати, які потрібно отримати |
| `--export-format` | `compact`, `terse`, `verbose` | Формат текстового експорту |
| `--show-sensitive` | `true` / `false` | Додавати чутливі значення до експорту |
| `--encrypt` | Непорожній пароль | Шифрувати `.backup` алгоритмом AES-SHA256 |
| `--clear-dns-cache` | `true` / `false` | Очистити DNS-кеш перед бінарною копією |
| `--clear-console-history` | `true` / `false` | Очистити історію консолі перед бінарною копією |

Для `--backup-type` значення `config` і `conf` також означають `configuration`.

*(N.B. Для `UseIncremental` немає окремого параметра CLI. Це налаштування задається в `option.cfg`, Configuration Editor або BackUP Master. Його призначення описано в [OPTIONS.md](OPTIONS.md).)*

<br />

### Сховище, архівування та журнали

| Параметр | Значення | Призначення |
|---|---|---|
| `--backup-root` | Шлях | Кореневий каталог сховища копій |
| `--use-net-folder` | `true` / `false` | Перевіряти монтування в пакетному режимі |
| `--monthly-archive` | `false` або число від `1` до `28` | Увімкнути календарне щомісячне архівування |
| `--log-level` | `0`, `1`, `2`, `3` | Докладність журналів і виведення в термінал |
| `--main-log-path` | Шлях до каталогу | Лише каталог для `main.log` |

Для `--monthly-archive` діє окреме правило: `true`/`yes`/`1`/`on` означають перший день місяця, а `false`/`no`/`0`/`off` вимикають архівування. Значення від `2` до `28` вибирають потрібний день.

Параметр вибирає день архівування, а не запускає його негайно. Правила цього режиму описано в [BACKUPS.md](BACKUPS.md#monthly-archive).

Для `--main-log-path` указуйте каталог, а не повний шлях з іменем `main.log`. На журнали пристроїв це налаштування не впливає.

<br />

### Джерело списку пристроїв і мова

| Параметр | Значення | Призначення |
|---|---|---|
| `--use-oxidized` | `true` / `false` | Імпортувати список з Oxidized |
| `--oxidized-home` | Шлях | Каталог налаштувань Oxidized із `config` і `router.db` |
| `--language` | `auto` або дволітерний код | Мова поточного інтерфейсу й журналів скрипта |

За `--language auto` мову вибирає локаль ОС. Її можна вказати явно, наприклад `ru`, `en` або `de`. Для російської та англійської окремий файл перекладу не потрібен; інші переклади завантажуються з файлів поруч зі скриптом. Якщо придатного перекладу немає, використовується англійська.
Докладніше дивіться в [LOCALIZATION.md](LOCALIZATION.md).

## Приклади запуску

**Зверніть увагу!!!**
За замовчуванням увімкнено додавання чутливих даних до експорту, очищення DNS-кешу й очищення історії консолі перед бінарною копією. У наведених нижче прикладах для одного пристрою очищення та чутливі дані в експорті вимкнено.

*(N.B. Паролі, передані через CLI, можуть бути видимими в історії оболонки та аргументах процесів. Це стосується й пароля шифрування `.backup`, який також може бути видимим в аргументах дочірнього процесу `ssh`. Докладніше дивіться в [SECURITY.md](SECURITY.md).)*

### Лише конфігурація `.rsc`, без чутливих даних

```bash
mikrotik-backup.sh --address=xxx.xxx.xxx.xxx --user=UserName --password=MySuperPassword --backup-type=configuration --show-sensitive=false
```

### Обидва формати, власне ім’я пристрою, без очищення

```bash
mikrotik-backup.sh --address=xxx.xxx.xxx.xxx --user=UserName --password=MySuperPassword --use-identity-name=false --device-name=edge-router --backup-type=both --show-sensitive=false --clear-dns-cache=false --clear-console-history=false
```

### Зашифрована бінарна копія

```bash
mikrotik-backup.sh --address=xxx.xxx.xxx.xxx --user=UserName --password=MySuperPassword --backup-type=binary --encrypt='ПАРОЛЬ_ШИФРУВАННЯ' --clear-dns-cache=false --clear-console-history=false
```

### Пакетний запуск з окремим каталогом і докладним журналюванням

Тут передбачається, що `option.cfg` і список пристроїв уже підготовлено:

```bash
mikrotik-backup.sh --backup-root=/srv/mikrotik-backups --log-level=3
```

Решта налаштувань для цього пакетного запуску береться з `option.cfg` і вбудованих значень.

## Якщо команду відхилено

Невідомий параметр, зайвий позиційний аргумент, пропущене або неприпустиме значення спричиняють помилку `12`. Резервне копіювання не починається. Правильність написання параметрів можна перевірити через `-h`.

**Порожні значення не можна передавати через CLI.**
Записи `--encrypt=''` і `--main-log-path=''` буде відхилено. Порожні значення `encrypt=` і `MainLogPath=` задаються в `option.cfg` або через Configuration Editor.

Коди завершення та їх значення наведено в розділі [Діагностика](TROUBLESHOOTING.md#result-codes).
